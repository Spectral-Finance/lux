# Rust Cargo Integration

Lux can manage Cargo manifests for Rust code used by agents, prisms, and native
extensions. `Lux.Rust.Cargo` provides a small Elixir API for generating
`Cargo.toml`, safely patching dependency sections, inspecting dependency state,
planning Cargo builds, and creating cache keys for CI.

## Initialize a Rust Project

```elixir
{:ok, project} =
  Lux.Rust.Cargo.init_project("priv/rust",
    name: "lux_native",
    dependencies: %{serde: %{version: "1", features: ["derive"]}}
  )

project.manifest_path
project.src_path
```

## Create a Manifest

```elixir
manifest =
  Lux.Rust.Cargo.manifest(
    name: "lux_native",
    version: "0.1.0",
    dependencies: %{
      serde: %{version: "1", features: ["derive"]},
      serde_json: "1",
      rustler: "^0.36"
    },
    dev_dependencies: %{
      proptest: "~1.4"
    },
    features: %{
      default: ["serde/derive"],
      nif: ["rustler"]
    }
  )

File.write!("priv/rust/Cargo.toml", Lux.Rust.Cargo.to_toml(manifest))
```

## Add Dependencies

```elixir
:ok =
  Lux.Rust.Cargo.add_dependency_to_file(
    "priv/rust/Cargo.toml",
    :tokio,
    %{version: "1", features: ["rt-multi-thread"]}
  )

:ok =
  Lux.Rust.Cargo.add_dependency_to_file(
    "priv/rust/Cargo.toml",
    :proptest,
    "~1.4",
    scope: :dev
  )
```

The dependency API supports registry, local path, and Git dependencies:

```elixir
:ok =
  Lux.Rust.Cargo.add_dependency_to_file(
    "priv/rust/Cargo.toml",
    :local_tool,
    %{path: "../local_tool"}
  )

:ok =
  Lux.Rust.Cargo.add_dependency_to_file(
    "priv/rust/Cargo.toml",
    :custom_crate,
    %{git: "https://github.com/example/custom_crate", tag: "v0.2.0"}
  )
```

The file-level helpers only patch dependency sections. They preserve unrelated
manifest content such as `[lib]`, `[[bin]]`, `[workspace]`, profiles, target
dependencies, and comments. The full manifest reader/writer is intentionally
limited to manifests generated by Lux.

## Inspect Versions

`resolve_dependencies/2` inspects manifest requirements against `Cargo.lock`
content and an optional version index. This keeps the function deterministic in
tests while keeping Cargo itself responsible for full dependency resolution.

```elixir
lockfile = File.read!("priv/rust/Cargo.lock")

resolved =
  Lux.Rust.Cargo.resolve_dependencies(manifest,
    lockfile: lockfile,
    version_index: %{
      "serde" => ["1.0.198", "1.0.197"],
      "tokio" => ["1.37.0", "1.36.0"]
    }
  )

resolved["serde"]
#=> %{requirement: "1", locked: "1.0.197", selected: "1.0.197", satisfied?: true}
```

You can also detect conflicting generated requirements before writing a
manifest:

```elixir
Lux.Rust.Cargo.dependency_conflicts(manifest)
```

## Build Integration

Use `build_plan/1` when an agent needs to inspect or display the Cargo commands
before executing them:

```elixir
Lux.Rust.Cargo.build_plan(
  manifest_path: "priv/rust/Cargo.toml",
  profile: :release,
  features: ["nif"]
)
```

Build and fetch plans use `--locked` automatically when a sibling `Cargo.lock`
exists. Pass `locked?: true` or `locked?: false` to override that behavior.

Run the build directly when Cargo is available:

```elixir
Lux.Rust.Cargo.build(
  manifest_path: "priv/rust/Cargo.toml",
  profile: :release,
  features: ["nif"]
)
```

For tests or dry runs:

```elixir
{:ok, %{command: command}} =
  Lux.Rust.Cargo.build(manifest_path: "priv/rust/Cargo.toml", dry_run: true)
```

## Caching

`cache_plan/2` creates a stable key from package metadata, dependencies,
features, and Cargo.lock package entries.

```elixir
cache =
  Lux.Rust.Cargo.cache_plan(manifest,
    lockfile: File.read!("priv/rust/Cargo.lock"),
    cache_root: ".lux/cargo"
  )

cache.key
cache.tracked_paths
```

Use the key with GitHub Actions, local task caches, or any CI cache provider.
